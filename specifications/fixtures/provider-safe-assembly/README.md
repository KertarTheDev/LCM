# Provider-Safe Assembly Fixture Skeleton

Owner: milestones 35-41.

These fixtures replace the unsafe mixed-assembly assumption that a raw context row maps to one provider message. Entries are skeletons until their owner milestone records commands, fixture data, OS/date/result, and report paths.

Expected fixture groups:

- `provider-safe-render-unit-assembly-v1`: render-unit assembly for raw messages, summaries, archive stubs, standalone markers, target-current-user continuation protection, render-only helpers, and retrieval cues through shared prompt preparation. Evidence must include deterministic `lcm-render-unit-v1` IDs, fixed placement-slot ordering, trusted render-unit origin metadata through cloned preparation inputs, protected/unprotected span discriminator checks, target-current-user spans unprotected unless they join a protocol group, single-unit and multi-unit protocol group aggregate-range checks, contiguous source-bearing span ranges per transform stage, `lcm-provider-transform-overhead-v1` pseudo render-unit IDs for provider-transform overhead, and non-empty `renderedSpans` with source kind, source handle, canonical order, effective order, zero-based half-open index range, placement slot, protection reason, protocol span ID, required provider family, transform stage, and `lcm-rendered-span-v1` span hash.
- `target-current-user-dedup-v1`: assembly receives explicit target-current-user identity, includes that turn exactly once as `target_current_user`, deduplicates any matching retained raw row, and fails closed when the target cannot be proven.
- `zero-message-span-v1`: render units that render zero provider messages produce `messageCount = 0` unprotected spans with source/order/slot/hash metadata and cannot create protected protocol spans.
- `tool-call-cue-adjacency-v1`: exact regression proving a retrieval cue never appears between assistant tool calls and matching tool results, including `lcm-protocol-span-v1` protected span IDs.
- `render-unit-budget-snapshot-v1`: source-selection hash, canonical empty-set request-snapshot-protection hash, render-unit order hash, effective-placement hash, token/cache identity, active-token reporting, `assemblyValidatorHash`, `lcm-context-restore-manifest-v2` snapshot restore, historical v1 metadata clearing including assembly-validator evidence, rebuild, request-snapshot cue IDs, `before_current_user` placement, visibility hashes, protected-span hash, `lcm-provider-transform-v1` hash, and provider-validator hash invalidation based on render units and rendered spans, including `lcm-provider-validator-pending-m39-v1` staleness.
- `retrieval-cue-safe-placement-v1`: `before_current_user` cue placement, first-class cue ID storage, payload cue-ID rejection, `cue_generation_id`, `cue_superseded_by_generation_id`, target-current-user cue identity, current-turn exclusion proof and fail-closed ambiguity, exclusion of completed same-turn assistant/tool output, errored output, pending/running rows, zero-part assistants, provider-tail rows, in-flight cue preservation, `cue_lifecycle_state` transitions, sorted unique `cue_ids_json`, deduplicated effective-order `render_unit_ids_json`, `lcm_provider_request_snapshots` state transitions where success/terminal provider error resolves, final-validation failure or abort/close cancels, TTL cleanup alone expires, stale request cleanup, transactional cue replacement, and cue non-model leak safety.
- `prompt-visibility-structural-helper-v1`: hidden queued-message exclusion for DB-loaded active context, required/excluded visibility and provenance table evidence, derived provenance filtering, structural render-helper classification with `lcmRenderOnly.kind`, stable `producer`, `operationID`, `createdAtMs`, `clonedPartID`, and `clonedMessageID`, trusted source-origin sidecar metadata, plugin-transform origin loss/duplication fail-closed cases, and preservation of quoted `<system-reminder>` / `<environment_details>` user or tool text.
- `provider-safe-hash-vectors-v1`: `provider-safe-hash-vectors-v1.json` stores canonical sorted-key JSON SHA-256 vectors for render-unit IDs, rendered spans, protocol spans, request-snapshot protection, render-unit order, effective placement, source selection, provider transform, and the pending pre-M39 provider-validator identity.
- `visibility-provenance-v1`: `visibility-provenance-v1.json` stores the machine-checkable visibility/provenance table and helper producer registry for milestone 38.
- `provider-family-classification-v1`: `provider-family-classification-v1.json` stores executable classifier vectors for Copilot, Anthropic, Vertex Anthropic, Mistral/Devstral, OpenAI, OpenAI-compatible custom, Ollama, interleaved-only, specific-transport interleaved, and generic provider families.
- `provider-protocol-matrix-v1`: final provider payload object validation after `ProviderTransform.message(...)` for OpenAI-compatible/Copilot, Anthropic, Mistral, interleaved reasoning, media fallback, large-file markers, pending/running tools, zero-part assistants, custom OpenAI-compatible/Ollama configs, and generic provider fallback. Evidence uses DR-083/DR-084/DR-085 provider-family classification and content-safe `lcm-normalized-provider-projection-v1` schemas with deterministic item/message/part indexes, provider family, roles, part kinds, safe-or-hashed provider/model/tool-call/tool-result/tool-name identifiers, adjacency groups, media fallback markers, reasoning markers, large-marker handles, render-unit/source handles, span hashes, protocol span IDs, transform stages, transform/validator hashes, and no raw text. It proves final provider branding covers one coherent payload object post-transform.
- `provider-safe-report-schemas-v1`: `provider-safe-report-schemas-v1.json` stores exact provider-safe report sections for `lcm-family-adaptation-audit-v1` and `release-scenario-script-v1`, including required IDs, status enum, allowed fields, and blocked-evidence requirements.
- `provider-safe-family-regression-v1`: packaged runtime/family regression proving the missing-tool-result class is removed and `lcm-family-adaptation-audit-v1` contains provider-safe check IDs: `provider-safe.render-unit-assembly`, `provider-safe.target-current-user-dedup`, `provider-safe.post-transform-validation`, `provider-safe.request-snapshot-cleanup`, `provider-safe.cue-lifecycle`, `provider-safe.snapshot-v2-repair`, and `provider-safe.missing-tool-result-regression`, with status values `passed`, `failed`, or `blocked` and no skipped required checks. Unsafe provider/model/tool IDs must appear only as hashes through the safe-or-hashed ID structure.
- `provider-safe-release-long-context-v1`: integrated long-context release evidence with provider-safe validation, request snapshot cleanup, cue lifecycle, snapshot v2 repair, packaged runtime, generic provider fallback, and the exact release scenario provider-safe step IDs `provider-safe.assembly-validation`, `provider-safe.final-provider-validation`, `provider-safe.request-snapshot-cleanup`, `provider-safe.cue-lifecycle`, `provider-safe.snapshot-v2-repair`, and `provider-safe.missing-tool-result-regression`, with status values `passed`, `failed`, or `blocked` and no skipped required steps.

Fixtures must store only content-safe evidence outside model-visible test inputs. Raw prompts, summaries, cue text, tool outputs, file bytes, provider payload text, and helper stdout/stderr must not be serialized into non-model reports unless the owning test fixture explicitly treats the file as model-visible fixture input.
