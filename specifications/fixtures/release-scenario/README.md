# Release Scenario Fixture Skeleton

Owner: milestone 27 for the report skeleton. Milestone 28 owns the executed release evidence that fills the skeleton with real commands, paths, captures, and pass/fail results.

Expected report: `release-scenario-script-v1`.

Skeleton artifact: `release-scenario-script-v1.skeleton.json`.

The machine-readable JSON report must include `scenarioID`, `specCommit`, `snapshotPath`, `runtimePath`, `os`, `date`, `steps`, `dbPath`, `artifactRoot`, `safeStatusCaptures`, and `result`.

Each step must include `stepID`, `command` or `manualAction`, `expected`, `actual`, `status`, and optional content-safe `safeError`. The script must rerun against the printed VSIX snapshot path without source-tree imports.

Milestone 41 refreshes the skeleton with provider-safe step IDs: `provider-safe.assembly-validation`, `provider-safe.final-provider-validation`, `provider-safe.request-snapshot-cleanup`, `provider-safe.cue-lifecycle`, `provider-safe.snapshot-v2-repair`, and `provider-safe.missing-tool-result-regression`. These steps use status values `passed`, `failed`, or `blocked`; required provider-safe steps must not be skipped. They are content-safe report evidence and must not serialize raw prompts, cue text, summaries, tool output, file bytes, or raw provider payloads.

Milestone 45 refreshes the skeleton with context-regression report check step IDs: `context-regression.context-fill-hard-ratio`, `context-regression.soft-backlog-pressure`, `context-regression.over-soft-nonblocking-scheduling`, `context-regression.maintenance-status-values`, `context-regression.deterministic-fallback-counter-label`, `context-regression.summary-quality-rejected-tiny`, `context-regression.summary-quality-accepted-useful`, `context-regression.provider-capacity-deferral`, `context-regression.provider-unavailable-connection-failure`, `context-regression.long-tool-output-source-preservation`, `context-regression.busy-status-finalizer`, `context-regression.hard-limit-fail-closed`, and `context-regression.no-stale-preparing-memory`. These report checks use the `context-regression-v1` schema and status values `passed`, `failed`, or `blocked`. The separate `context-regression.release-context-regression` release-script step validates the aggregate report but is not itself a `context-regression-v1` check ID. Deterministic fake/local OpenAI-compatible evidence must pass.

Milestone 28 adds the runnable report generator under `packages/opencode` as `lcm:release-long-context`. The generator automates source/runtime DB smoke checks where local paths are available. Current local evidence also scripts deterministic VSCode LCM settings, inline status, transport, prewarm, file, and map coverage through the `packages/kilo-vscode` and `packages/opencode` suite registry. VSCode install remains evidence-backed unless matching local artifact paths are supplied. External platform smokes use the `lcm-platform-packaged-runtime-smoke-v1` JSON schema generated by `lcm:platform-runtime-smoke` and consumed through the report generator's `--platform-evidence-dir` option; filename-only evidence and target labels that do not match recorded OS/architecture are rejected. Other external owners provide one `.json`, `.txt`, or `.md` evidence file per manual `stepID` through `--manual-evidence-dir`.
